# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Bun + Turborepo monorepo: `apps/web` (TanStack Start on a Cloudflare Worker), `packages/db`, `packages/services`.

## Commands

- `bun test` runs everything. One file: `bun test packages/services/src/bookings.test.ts`; one test: add `-t "name"`.
- `bun run check` is lint (Ultracite/Biome) plus typecheck. `bun run fix` formats. The pre-commit hook runs `ultracite fix` and re-stages, so commits can change files and can fail on unfixable lint.
- `bun run dev` applies local migrations and `packages/db/seed.sql` first, so no Cloudflare account is needed. Local DB is `apps/web/.wrangler`; delete it to reset.

## Rules

**Layering: route → tRPC router → service → db query function.**
- Put business rules and zod validation in `packages/services`, never in routers or `packages/db`. Why: services must work without tRPC/Hono/env (scripts, tests), and db functions are shared by D1 and `bun:sqlite`.
- Routers stay thin: input schema from the service, one service call. Services re-parse input, so don't assume the router validated it.
- Throw `ServiceError` subclasses (`NotFoundError`, `ValidationError`, `ConflictError`, `ForbiddenError`) from services. Why: the tRPC layer maps them to HTTP codes; a plain `Error` becomes a 500.
- Service mutations take the acting member's id first and call `requireMember`/`requireAdmin`. Why: there is no auth, so these checks are the only permission control.

**Database access.**
- `@repo/db` functions take a `Database` (any drizzle SQLite instance); never read `env`/bindings there. Only `apps/web/src/server/trpc/context.ts` reads `env.DB`. Why: tests swap D1 for in-memory `bun:sqlite` with the real migrations.
- Return plain JSON shapes (string ids, ISO dates), not row types. Why: tRPC serializes as JSON.

**Imports and new modules.**
- Browser code may import only `@repo/db/shared`. Why: every other `@repo/db` entry imports drizzle and would bloat the client bundle.
- No barrel files. A new module is `src/<name>.ts` plus an `exports` line in that package's `package.json`; a new service also needs registering in `context.ts`. Why: the entry points are the server/browser boundary.
- `notes` and `bookings` are the templates to copy.

**Schema changes.**
- After editing `packages/db/src/schema.ts`, run `bun run generate` in `packages/db` and commit `migrations/` including `migrations/meta/`. Why: drizzle diffs against the snapshot there; without it the next generate recreates the tables. Wrangler applies migrations, not drizzle-kit.

**Auth.** `ctx.userId` is always null and `protectedProcedure` always rejects. Mutations take `actorId` in their input; don't use `protectedProcedure` for team features until auth exists.

## Gotchas

- `worker-configuration.d.ts` (the `Env` type) is generated by `bun run cf-typegen`; typecheck fails on a stale or missing one. It runs on `bun install`.
- `apps/web/wrangler.jsonc` holds a real D1 `database_id` and has no `account_id`; `deploy` and the `:remote` db scripts act on that database using whichever Cloudflare account is logged in.
- `#/*` aliases `apps/web/src/*`.
